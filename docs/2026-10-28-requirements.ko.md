# AI Co-worker Without Me 요구사항 (초안, 2026-10-28)

## 무엇을 만드나

동료끼리 각자 쓰는 AI(Claude Code, Codex)가 직접 묻고 답하게 해 주는 MCP다.

지금은 사람이 AI 결과를 복사해 메신저로 보내고, 받은 사람이 그걸 다시 자기 AI에 붙여넣는다. 이 반복을 없앤다. AI끼리 주고받는 동안 사람은 지켜보고, 끝나면 합의문을 놓고 논의한다.

## 쓰는 사람과 환경

- 각자 개인 계정으로 쓰는 Claude Code(Pro·Max)와 Codex. 회사 Team·Enterprise 계정은 대상이 아니다.
- Mac과 Windows 모두 된다. Windows에서 신경 쓸 것은 셋이다.
  - **방화벽 허용 창:** 처음 포트를 열 때 Windows 방화벽이 허용할지 묻는다. 「개인 네트워크」로 허용해야 한다.
  - **`컴퓨터이름.local`:** Windows에서는 이 이름으로 찾기가 잘 안 될 수 있다. 그래서 연결 코드에 IP 주소를 항상 함께 넣는다.
  - **WSL 안에서 Claude나 Codex를 돌리는 경우:** WSL은 기본 설정에서 바깥과 다른 네트워크에 있어서 밖에서 그 포트로 들어올 수 없다. WSL 네트워크를 미러 모드로 바꿔야 한다.
- **1차는 사내망과 회사 VPN이다.** VPN으로 들어온 PC도 사내 IP를 받으므로 사내망과 같게 다룬다. 동료 PC에 Tailscale을 깔 수 없어서 Tailscale은 전제로 하지 않는다.
- **2차는 외부망이다.** VPN 없이 서로 다른 공유기 아래에 있는 PC끼리는 바로 연결되지 않아서, 중간에서 이어 주는 방법이 필요하다.
  - **중계 서버를 직접 띄우는 방식으로 정했다(2026-10-29, 사람이 정함).** 서버를 띄우는 데 돈이 들므로, 이 저장소에는 중계 서버 소스와 배포 파일만 공개 소스로 둔다. 서버와 도메인은 띄우는 사람이 마련한다.
  - 두 PC는 중계 서버로 나가는 연결만 한다. 내용은 양 끝에서 암호화한 그대로 지나가서 중계 서버는 읽지 못한다. 다른 후보였던 공개 무료 중계(시험용 서비스라 끊기거나 막힐 수 있다)와 공유기 포트 자동 열기(공유기마다 되고 안 되고, 회사망에서는 못 쓴다)는 쓰지 않는다.
- **사내 방화벽과 VPN에서 PC끼리 통신이 되는지 확인해야 한다.** 사내망은 「기본 차단, 필요한 통신만 허용」으로 운영되는 경우가 많다. 그러면 PC끼리 이 포트로 통신하는 것을 허용 목록에 올려야 한다. VPN도 서버만 열어 두고 PC끼리는 막는 경우가 있다.
- 2026-10-28에 같은 Mac 안에서 실제 Codex 세션이 브릿지를 열고, 실제 Claude Code 세션이 연결 코드로 붙어 질문하고 답을 받고 닫기까지 성공했다. Codex는 자기 폴더의 메모를 읽고 답했고, 상대가 닫자 스스로 기다리기를 멈췄다. 끝난 뒤 열린 포트와 남은 파일은 없었다.
- 2026-10-28에 집 Mac과 회사 Mac mini 사이를 Tailscale로 연결해 봤다. 다른 네트워크에 있는 IP로 접속하는 상황이 VPN과 같아서, Tailscale은 개발 중 시험에만 쓴다.
- 2026-10-29에 같은 Mac 안에서 Channels로 켠 실제 Claude Code(2.1.312) 세션이 연결 코드로 붙었다. 상대가 보낸 질문이 세션에 바로 들어왔고, AI는 기다리기 도구를 부르지 않고 6초 만에 답했다. 상대가 닫은 것도 바로 알았다.

- 2026-10-29에 플러그인으로 설치해 시험했다(이 저장소를 로컬 마켓플레이스로 추가).

  - Codex(0.165.0): 의존성 없이 복사된 플러그인이 처음 켤 때 스스로 패키지를 깔았다. 기다리기는 승인 없이 돌고, 연결·답하기·닫기는 승인을 물었다. 상대가 쓴 합의문을 받아 자기가 확인한 내용과 맞춰 보고, 고칠 게 없어 다시 쓰지 않았다.

- 2026-10-29에 GitHub에 올린 뒤 README 명령 그대로 플러그인을 설치해 시험했다. Claude Code는 `claude plugin install coworker --marketplace BrilliantTiger/ai-coworker-without-me`, Codex는 `codex plugin marketplace add`와 `codex plugin add`다. 고친 것이 둘이다.
  - 예전에 직접 등록한 coworker가 남은 PC에서 플러그인을 채널로 켜면 coworker가 두 개 뜬다. 직접 등록한 쪽도 실행 인자에서 개발용 채널 옵션을 보고 자기도 채널이라고 알았다. AI가 그쪽 `connect`를 고르자 Claude Code가 그 서버의 알림을 버렸고(디버그 로그 「coworker not in --channels list」), 연결 직후 온 질문을 놓쳤다. 이제 플러그인으로 뜬 서버(`CLAUDE_PLUGIN_ROOT`가 있다)는 `plugin:coworker@…`일 때만, 직접 등록한 서버는 `server:coworker`일 때만 채널로 본다. 고친 뒤 실제 세션에서 플러그인 쪽은 채널로, 직접 등록한 쪽은 기다리기 도구로 받아 둘 다 답했다.
  - Codex는 설치 뒤 첫 세션을 켤 때 이미 띄운 MCP의 플러그인 폴더를 같은 경로의 새 폴더로 바꾼다(0.165.0). 지워진 폴더에 남은 MCP에서 `process.cwd()`가 `uv_cwd` 오류를 내 `connect`가 두 번 다 실패했다. 그 세션에서 깐 패키지도 옛 폴더와 함께 사라졌다. 두 번째 세션부터는 폴더가 그대로다. 이제 작업 폴더를 못 읽으면 셸의 `PWD`를 쓰고, 패키지를 깐 뒤 사라졌으면 다시 깐다.
- 2026-10-29에 Windows PC의 Bun 1.3.7은 새 Bun(1.4.x)이 만든 `bun.lock`(`lockfileVersion` 2)을 읽지 못했다(「Unknown lockfile version」). 플러그인이 처음 켤 때 하는 `bun install --frozen-lockfile --production`이 실패해서, Bun이 오래된 PC에서는 플러그인이 켜지지 않았다. `--production`도 lock 파일을 고정한 것처럼 다뤄 같이 실패했다. 이제 실패하면 `bun install --omit=dev`로 package.json의 범위대로 깐다. 같은 PC에서 이렇게 깔리고 서버가 뜨는 것을 확인했다. 직접 받은 저장소에서 오래된 Bun으로 `bun install`을 하면 `bun.lock`이 옛 형식으로 다시 써져 바뀐 파일로 나온다.
- 2026-10-30에 업데이트를 시험했다. GitHub에서 플러그인을 설치한 뒤 INSTALL.md의 업데이트 명령으로 새 커밋(607b9ca → 16b173c)까지 올라오는지 봤다. 이 Mac의 Claude Code와 Codex, Windows PC의 Claude Code에서 모두 올라왔다. Windows PC에는 Codex가 없어서 Windows의 Codex는 시험하지 못했다. Codex는 `marketplace upgrade` 뒤에 `add`만 다시 해도 플러그인 폴더를 통째로 바꿔서 지우는 단계가 필요 없었다.

Claude Code에는 플러그인 설치 직후에 안내를 띄우는 방법도 없다. 그래서 INSTALL.md에 별칭 `claude-cw`를 적고(Mac은 `alias`, Windows는 `claude`가 있는 폴더의 `claude-cw.cmd`), 플러그인의 세션 시작 훅이 옵션 없이 처음 켠 세션에 한 번 안내한다. 이 훅은 Claude Code 플러그인 설정(`.claude-plugin/plugin.json`)에만 넣었다. 실제 세션에서 처음에만 안내가 뜨고, 다시 켜거나 채널로 켜면 뜨지 않았다. Windows PC에서 `claude-cw.cmd`가 PowerShell과 명령 프롬프트 양쪽에서 실행됐다.

Codex가 도구 호출을 60초까지만 기다리고, 사람은 그보다 오래 걸릴 수 있어서다. 사람이 고르거나 직접 쓰면, MCP가 그 결정을 상대에게 「사람이 정했습니다: …」로 보내고 「사람이 정함」 표시를 붙인다. 상대 AI의 알림과 양쪽 대화 보기 화면에 그 표시가 나온다. 이쪽 AI는 결정 알림(decision)을 받아 무엇을 보냈는지 사람에게 한 줄로 전한다. 상대에게는 번호를 빼고 고른 말만 보낸다. 번호는 상대가 보지 못한 목록의 것이기 때문이다. 사람이 답하지 않고 창을 닫으면 상대에게는 아무것도 가지 않고, AI가 번호 보기로 다시 묻는다. 답하지 않은 창은 브릿지 상태와 함께 저장해서, 같은 세션을 다시 켜면 다시 띄운다. 창은 시간으로 닫지 않는다. 창을 띄울 수 없는 앱이면 AI가 번호를 붙여 묻고, 사람의 답을 「사람이 정함」으로 보낸다. 합의문의 「사람이 정할 것」과 상대가 이 PC에서 무언가 바꿔 달라는 부탁도 같은 창으로 묻는다. 합의문을 쓴 대화에도 사람의 결정은 보낼 수 있다. 시험: 전체 83개. 실제 Claude Code 2.1.322 세션(bypass)에서 시험용 상대가 결정이 필요한 질문을 보내자, AI가 보기 둘(월요일에 「(추천)」)로 창을 띄웠다. 2번을 고르자 상대가 「사람이 정했습니다: 다음 주 월요일(11/16) 10시」를 사람이 정한 답으로 받았고, AI는 스스로 깨어나 보냈다고 알렸다.
- 2026-11-11에 같은 이름의 연결이 둘 남았을 때 이름으로 물으면 막히던 것을 고쳤다(사람이 정함: 「응 고치고」). token-pet에서 동료가 세션을 새로 켜고 새 코드로 다시 붙자, 옛 연결과 새 연결이 같은 이름으로 남았다. 이름으로 물으면 「matches more than one session」으로 막혔다. 이제 이름이 같은 세션이 여럿이면, 그 이름은 바로 닿는 쪽을 가리킨다. 바로 닿는 쪽이 없으면 이쪽에 와서 가져가는 것 가운데 나중에 붙은 쪽을, 그것도 없으면 나중에 붙은 쪽을 가리킨다. 막 꺼진 옛 세션도 1분 동안은 가져가던 흔적이 남아서, 가져가기만으로는 둘을 가리지 않는다. 「전체에게」도 이름마다 같은 기준으로 하나만 보낸다(바로 닿는 쪽이 여럿이면 모두). 바로 닿는 같은 이름이 둘이면 막고, 연결 보기에 새로 넣은 짧은 ID로 고르게 한다. 옛 연결은 지우지 않는다(사람이 닫거나 세션이 끝날 때까지 둔다).
- 2026-11-11에 새 세션이 앞 세션의 브릿지를 이어받게 했다(사람이 정함: 「질답 세션이 다른 것으로 옮겨졌을 때 기존 접근 키와 연결되었던 세션 ID를 가지고 새 세션에서 연결 재개」, 「context가 차서 새 세션으로 연결할 때 계속 발급받아야 해서 불편하다」, 「재연결되면 히스토리까지 싹 다 볼 수 있어야」). 그전에도 되살리기(resume)로 앞 세션의 `session_id`를 주면 이어졌지만, 셋이 막혔다. 새 세션은 그 ID를 몰랐다. 앞 세션이 아직 켜져 있으면 거절했다. 이어받은 브릿지가 앞 세션 이름표로 저장돼서 새 세션을 다시 켜면 돌아오지 않았다. 이제 연결 보기가 이 PC에 앞 세션들이 남긴 브릿지를 보여 준다(이름, 연결된 세션, 대화 수, 다른 세션에서 돌고 있는지). 되살리기는 `session_id`나 브릿지 이름(일부)으로 한다. 앞 세션에서 아직 돌고 있으면, 새 세션이 그 브릿지의 비밀키로 봉인한 넘겨 달라는 요청을 그 포트로 보낸다. 앞 세션은 상태를 저장하고 멈춘 뒤, 띄워 둔 질문 창과 보기 화면을 닫는다. 그리고 AI에게 「옮겨 갔으니 그만 들어라」를 알린다. 저장된 상태를 읽을 수 있는 이 PC의 사용자만 이 요청을 만들 수 있다. 앞 세션은 같은 브릿지를 다시 열지 않고, 다시 열면 새 이름표로 새로 시작한다. 같은 키가 두 곳에서 돌지 않게 하려는 것이다. Claude Code처럼 자기 세션 ID가 있는 세션은 이어받은 브릿지를 자기 이름표로 옮겨 저장한다. 대화 기록은 모두 따라온다. 대화 보기는 앞 세션의 포트가 빌 때까지 기다렸다가 같은 링크로 연다. 이어받은 결과에는 대화 목록이 들어 있고, AI는 아직 진행 중인 대화를 read_conversation으로 다시 읽고 이어 간다. 답하지 않은 질문 창도 다시 뜬다. 시험: 전체 84개. 실제 Claude Code 2.1.322 새 세션에 「이전 질답 세션 연결 이어받아」라고만 했다. 앞 세션이 켜져 있는 채로 AI가 이름으로 이어받았다. 앞 세션은 옮겨 갔다는 알림을 받았고, 상대는 새 코드 없이 다시 연결됐다는 알림을 받았다. AI는 대화 두 건을 읽어 어디까지 왔는지 보고했다. 상대가 열려 있던 질문에 답하자 새 세션이 받아 보고했다. 대화 보기 링크는 앞 세션 것 그대로였고 두 대화의 메시지가 모두 보였다.
- 2026-11-11에 다시 켠 세션이 사람 손 없이 바로 다시 듣게 했다(사람이 정함: 「이런 이슈는 없어야 하지 않냐? restart를 하면 바로 다시 읽어야지」, 「이미 질문이 쌓여 있을 때는?」). 동료 세션이 다시 켜진 뒤 질문이 그 세션의 coworker까지 갔는데(delivered), 23분 동안 아무도 읽지 않았다. 채널 없이 켠 Claude Code는 AI가 걸어 둔 백그라운드 대기 명령이 끝나야 깬다. 그런데 다시 켜면 그 명령이 사라지고, 사람이 말을 걸기 전까지 아무도 다시 걸지 않았다. Claude Code 2.1.322의 훅에는 `asyncRewake`가 있다. 백그라운드로 돌다가 코드 2로 끝나면 그 출력으로 AI를 깨운다. 코드에서 확인했고, 따로 정하지 않으면 10분 뒤 끝나서 `timeout`을 타이머가 받는 끝(2147483초)으로 줬다. 그래서 GitHub판 플러그인에 세션 시작 훅을 하나 넣었다. 다시 켤 때(`resume`)만 `coworker.js wake`를 띄운다. 이 명령은 저장된 상태에서 이 세션의 대화 보기 서버를 찾아 새 기다리는 주소(`/wake`)에 붙는다. 소식이 이미 쌓여 있으면 바로, 아니면 올 때 한 줄을 쓰고 코드 2로 끝난다. AI가 스스로 대기를 걸면 훅의 기다림은 끝나서 두 번 깨우지 않는다. 채널로 받는 세션이거나 되살릴 브릿지가 없으면 바로 조용히 끝난다. 끄기 전에 와서 안 읽은 소식은 상태에 저장돼 되살아나고, 꺼져 있는 동안 상대가 보낸 것은 상대가 들고 있다가 넘기므로, 쌓인 질문도 다시 켜자마자 깨운다. 11-09에는 디렉터리 심사 때문에 플러그인의 세션 시작 훅을 없앴다. 지금은 디렉터리판(`directory/`)이 따로 있고 거기에는 여전히 훅이 없어서, GitHub판에만 다시 넣었다. Codex와 디렉터리판은 이렇게 깨울 방법이 없어 여전히 사람이 한 마디 해야 한다. 브릿지는 열자마자 한 번 바로 저장하게 했다. 열고 곧 꺼져도 다시 켜거나 이어받을 수 있게 하려는 것이다. 시험: 전체 87개. 실제 Claude Code 2.1.322 세션(bypass, 같은 훅을 설정 파일로 넣음)을 연결해 듣게 한 뒤 끄고 `claude --resume`으로 다시 켰다. 아무것도 치지 않은 상태에서 상대가 질문하자 「coworker: new message after the restart」로 AI가 깨어 6초 만에 답했다. 그 과정에서 Claude Code는 백그라운드 작업이 돌고 있으면 `/restart`를 거절한다는 것도 확인했다.

## 흐름

1. 사람이 자기 Claude나 Codex 세션에서 브릿지를 연다. 그 세션의 MCP가 포트를 열고 연결 코드를 보여 준다.
2. 사람이 연결 코드를 메신저로 동료에게 보낸다. 동료가 자기 세션에 코드를 넣으면 두 세션이 연결된다.
3. 연결되면 양쪽 AI는 사람이 「그만」이라고 할 때까지 계속 듣는다. 한 번 주고받고 끝나지 않는다.
4. 양쪽 다 질문하고 답한다.
5. 질문을 받거나, 답하거나, 답을 받을 때마다 AI가 그 세션에서 바로 사람에게 정리해서 알린다. 누가, 무엇을 물었고, 무엇을 답했고, 사실에서 나온 답인지 사람이 정한 답인지를 적는다.
6. 이미 정해진 것(코드, 문서, 이미 내린 결정, 사람이 이미 말한 것에 답이 있는 것)은 AI가 바로 답한다.
7. 결정이 필요한 것(선택지 중 고르기, 우선순위, 범위, 일정 등)은 AI가 정하지 않는다. 상대에게 「사람에게 확인 중」이라고 알리고, 자기 사람에게 질문 창을 띄워 번호 붙은 선택지와 추천, 직접 입력 칸으로 묻는다. 사람이 고르면 그 결정이 「사람이 정함」 표시와 함께 답으로 간다(2026-11-11).
8. 끝나면 AI가 합의문을 쓴다. 합의문에는 결론, 확인한 사실과 근거(파일·실행 결과), 추측, 의견이 갈린 점, 사람이 정해야 할 것을 나눠 적는다.

## 연결 구조

중앙 서버가 없다. 세션끼리 직접 연결한다.

- **브릿지는 세션별로 연다.** MCP는 모든 세션에 들어 있지만, 사람이 브릿지를 연 세션만 포트를 연다. 세션이 닫히면 포트와 연결도 끝난다.
- **포트는 직접 지정할 수 있다.** 지정하지 않으면 정해 둔 범위(예: 7700~7799)에서 비어 있는 번호를 쓴다. 범위를 정해 두는 건 사내 방화벽에 허용을 요청하기 쉽게 하려는 것이다. 한 PC에서 세션 여러 개가 브릿지를 열면 각자 다른 포트로 뜬다.
- **연결 코드에는 주소 목록, 포트, 암호화용 공개키가 들어 있다.** 주소 목록은 사내 IP, VPN 주소, `컴퓨터이름.local`이다. 받는 쪽은 앞에서부터 차례로 시도한다.
- **연결 조합은 자유롭다.** 내 Claude와 동료의 Codex를 연결할 수 있고, 같은 PC 안의 Claude와 Codex도 연결할 수 있다. 한 세션이 여러 세션과 동시에 연결될 수도 있다.
- **같은 프로젝트를 하는 사람들은 그룹으로 묶인다(2026-10-29 추가).** 연결 코드는 기본이 그룹 코드다. 코드로 들어온 세션은 코드를 준 세션의 그룹 전체에 소개되어 서로 연결된다. 소개받은 세션끼리는 코드 없이 공개키로 서로를 알아본다. 둘만 이어지는 개인용 코드도 있다.
- **기본 포트 범위는 바꿀 수 있다(2026-10-29 추가).** 환경변수 `COWORKER_PORTS`(예: `9000-9010`)로 정한다. 없으면 7700~7799를 쓴다.
- **어느 망이든 자체 암호화한다.** 연결 코드로 연결한 세션이 보낸 것만 받는다.
- **잠깐 끊기면** 보낸 쪽이 보관하고 있다가 다시 보낸다.
- **한쪽만 들어오는 연결을 받을 수 있어도 된다.** 방화벽에 막힌 쪽은 상대에게 먼저 접속해서 자기 앞으로 온 메시지를 가져가고, 받았다고 알려야 상대가 지운다.
- **세션을 다시 열면 연결 코드를 다시 주고받는다.** 연결을 기억해 두는 기능은 써 보고 필요하면 붙인다.
- **중계 서버를 쓰면 주소 목록 끝에 중계 서버의 우편함 주소가 붙는다(2026-10-29).** 세션마다 우편함이 하나 생기고, 꺼내 가는 것은 그 세션만 한다. 보내는 쪽은 상대 우편함에 넣고 답을 기다린다. 바로 연결할 때와 같은 요청·답이 그대로 오가고, 같은 망이면 바로 닿는 주소를 먼저 쓴다. 중계 서버 키를 정하면 키를 아는 세션만 우편함을 연다. 한쪽만 중계 서버를 설정해도 된다.

## 메시지가 오면 AI가 반응하는 방법

상대 메시지가 오면 내 AI가 알아서 읽고 답해야, 사람은 지켜보기만 하면 된다.

| 도구 | 방법 |
|---|---|
| Claude Code | **Channels를 쓴다.** 플러그인으로 설치했으면 `claude --dangerously-load-development-channels plugin:coworker@ai-coworker-without-me`, 직접 등록했으면 `claude --dangerously-load-development-channels server:coworker`로 켠다. `--channels`는 Anthropic이 승인한 채널만 받아서 쓸 수 없다. 메시지가 오면 세션에 바로 들어가고 AI가 반응한다. 기다리는 동안에는 사용량이 들지 않는다. 다만 직접 만든 채널이라 켤 때마다 개발용 옵션을 붙여야 하고 경고 화면이 한 번 뜬다. Claude Code는 MCP를 채널로 등록했는지 알려 주지 않고, 채널로 등록되지 않은 세션에 보낸 알림은 오류 없이 버린다. 그래서 MCP는 자기를 띄운 Claude Code의 개발용 채널 옵션에 자기가 적혀 있을 때만 채널로 보낸다. 플러그인으로 뜬 서버는 `plugin:coworker@…`, 직접 등록한 서버는 `server:coworker`다(2026-10-29) |
| Codex | **대기 도구를 쓴다.** AI가 「메시지 기다리기」를 호출해 두면 메시지가 왔을 때 돌아온다. Codex는 도구 호출을 60초까지만 기다려서 50초(최대 55초)마다 다시 호출하고, 그때마다 사용량이 조금씩 든다 |
| Channels 없이 켠 Claude Code | **기다리는 명령을 백그라운드로 걸어 둔다(2026-11-10).** 브릿지를 열거나 연결하면 MCP가 `curl -s http://127.0.0.1:<포트>/<토큰>/next`를 주고, AI는 이 명령을 Bash 백그라운드로 걸어 둔 뒤 차례를 끝낸다. 기다리는 동안에도 사람이 바로 말을 걸 수 있다. 소식이 오면 명령이 끝나고 Claude Code가 AI를 깨운다. AI는 inbox로 읽고 반응한 뒤 다시 걸어 둔다. 기다리는 동안 사용량이 들지 않는다. 명령을 돌릴 수 없으면 예전처럼 대기 도구를 시간 제한 없이 부른다(2분쯤 지나면 Claude Code가 그 호출을 백그라운드로 넘긴다. 30분 동안 조용한 호출이 끊기지 않게 5분마다 진행 알림을 보낸다) |

## AI가 쓰는 도구

| 도구 | 하는 일 |
|---|---|
| 브릿지 열기 | 포트를 열고 연결 코드를 보여 준다. 포트를 지정할 수 있다. 다시 켜진 뒤나 새 세션으로 옮겼을 때는 앞 세션의 `session_id`나 브릿지 이름으로 같은 브릿지를 이어받는다(resume). 앞 세션이 아직 돌고 있으면 그 세션이 넘겨주고 멈춘다 |
| 연결하기 | 받은 연결 코드로 상대 세션에 연결한다. 이쪽 이름을 정할 수 있다 |
| 연결 보기 | 연결된 세션 목록과 각각 지금 닿는지 보여 준다 |
| 질문 보내기 | 연결된 세션(여러 개면 지정)에 질문과 지금까지 알아낸 것을 보낸다 |
| 답하기 | 대화에 답을 단다 |
| 메시지 기다리기 | 새 메시지가 올 때까지 기다린다 |
| 합의문 쓰기 | 대화를 마치고 합의문을 양쪽에 남긴다. 상대에게 보내고, 양쪽 PC의 `~/.coworker/agreements/`에 대화 기록과 함께 파일로 남긴다. 사실마다 근거와 직접 확인한 쪽을 적는다. 받은 쪽이 동의하지 않으면 자기 판을 따로 쓴다. 합의문을 쓴 대화에는 더 답하지 않는다 |
| 사람에게 묻기 | 결정이 필요하면 상대에게 「사람에게 확인 중」이라고 알리고, 자기 사람에게 질문 창(번호 붙은 선택지, 추천 표시, 직접 입력)을 띄운다. 사람이 고르면 그 결정을 「사람이 정함」으로 상대에게 보낸다 |
| 브릿지 닫기 | 포트를 닫고 연결을 끊는다 |

질문 하나가 대화 하나다. 한 세션이 여러 대화를 동시에 가질 수 있다.

질문은 한 명, 몇 명, 전체에게 보낼 수 있다(2026-10-29 추가). 여럿에게 보내면 받는 사람마다 대화가 따로 생기고 같은 질문 묶음으로 묶인다. 답 받는 방법은 둘이다. 「모두 답」은 받은 사람 모두에게서 답을 받는다. 「한 명만 답」은 먼저 온 답 하나를 받고, 나머지 사람의 대화를 마감한다. 받는 사람끼리는 서로의 답을 보지 않는다. 대화마다 상태가 있다. 답 기다리는 중, 내 차례, 내 사람에게 확인 중, 상대가 자기 사람에게 확인 중, 합의문 작성됨, 마감(다른 사람이 먼저 답함)이다.

## 안전 규칙

- **보내기 전 확인은 Claude·Codex의 도구 허용 창으로 한다.** 매번 보고 허용해도 되고, 믿을 만하면 「항상 허용」으로 흘려보내도 된다. 기다리기처럼 읽기만 하는 도구는 허용 창 없이 쓰게 설정할 수 있다. 비밀값으로 보이는 내용은 자동으로 막는다. 질문·배경·답·알림·합의문을 보내기 전에 흔한 열쇠·토큰 모양(개인키, AWS·GitHub·GitLab·Slack·OpenAI·Anthropic·Stripe·Google 키, JWT, Bearer 토큰), 주소에 든 비밀번호, `password=…` 같은 대입을 찾는다. 자리표시(`<redacted>`, `***`)와 코드에서 값을 읽는 곳(`process.env.API_KEY`)은 넘긴다. 막으면 아무것도 보내지 않고, 오류에도 앞 네 글자만 보여 준다(2026-10-29).
- **상대 메시지는 참고 자료로만 쓴다.** 상대 메시지를 근거로 파일을 고치거나 명령을 실행하려면 사람 승인이 있어야 한다. 상대가 비밀값이나 파일 내용을 달라고 해도 그대로 따르지 않는다.
- **왕복 횟수에 상한을 두지 않는다(2026-10-30, 사람이 정함).** 처음에는 대화 하나당 왕복 6번(메시지 12개)에서 멈추고 사람에게 넘겼지만 없앴다. 대화는 질문한 쪽이 합의문을 쓰거나, 사람이 그만하라고 할 때 끝난다.
- **합의문에는 확인한 사실과 추측을 나눠 적는다.** AI 둘이 서로 맞장구치다 틀린 결론에 합의하는 것을 막기 위해서다.
- **Channels의 원격 실행 승인 기능은 끈다.** 켜 두면 상대가 내 PC에서 명령 실행을 승인할 수 있게 된다.
- **개인 계정의 학습 설정을 확인한다.** 각자 대화를 학습에 쓰지 않도록 설정했는지 확인한다. README의 「지켜야 할 것」에 Claude와 Codex 각각 어디서 끄는지 적었다.

## 아직 정할 것

- **포트 범위:** 7700~7799는 기본값이다. 사내 방화벽에 허용을 요청할 범위가 정해지면 `COWORKER_PORTS`로 맞춘다.
- ~~**2차 외부망 방식**~~: 중계 서버를 직접 띄우는 방식으로 정했다(2026-10-29). 위 「쓰는 사람과 환경」에 있다.
- **중계 서버를 어디에 띄울지:** 띄우는 사람이 정한다. 이 저장소에는 소스와 배포 파일(`relay/`)만 있다.
- **만드는 언어:** TypeScript(Bun)를 추천한다. MCP 공식 SDK가 TypeScript이고, Claude Channels 예제와 공식 채널 플러그인도 Bun으로 되어 있다.

## 만드는 순서

1. 브릿지 열기, 연결하기, 주고받기: 세션별 포트, 연결 코드, 암호화. 시험은 세 가지로 한다.
   - 같은 PC 안의 Claude와 Codex
   - 집 Mac과 같은 네트워크에 있는 Windows PC: 사내망과 같은 조건에서 직접 연결과 Windows 동작을 함께 확인한다
   - 집 Mac과 회사 Mac mini(Tailscale): VPN과 같은 조건, 즉 다른 네트워크에 있는 IP로 접속하는 경우를 확인한다
   - 회사에서 동료 PC와: 실제 사내망과 VPN에서 확인한다
2. 메시지가 오면 AI가 반응하게 하기: Claude는 Channels, Codex는 대기 도구.
3. 합의문, 비밀값 막기. (왕복 상한도 만들었다가 2026-10-30에 없앴다.)
4. 플러그인으로 묶어 Claude와 Codex에 한 번에 설치되게 하기.
5. 2차: VPN 없는 외부망에서도 연결되게 하기.
